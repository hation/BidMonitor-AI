# 机会分析关键词界面化编辑 — 设计文档

- 日期：2026-11-23
- 状态：已确认
- 背景：机会分析规则引擎已上线（上一迭代），关键词存 `workbench_settings`（key=`opportunity_keywords`），本子项目让其在设置页可视化编辑，保存即生效
- 迭代边界：子项目 1（本 spec）只做关键词界面编辑；AI 精读标书为子项目 2，另行 spec

## 1. 需求与目标

用户业务方向会变（当前服务器/IT/AI），关键词词表应能在界面调整，无需改库或重启。本子项目在"数据与成员"设置页新增"机会分析关键词"面板，三档文本框编辑，保存即生效。

## 2. 已确认的决策

- **编辑粒度**：三档文本框（核心/次要/排除），每词一行，整体覆盖保存。
- **生效时机**：保存即生效——配置存 `workbench_settings`，`search()` 每次实时读取，无需重启。
- **附带内容**：面板带说明文案（业务方向 + 三档逻辑 + 意向线索规则）。

## 3. 现状关键事实（已核实）

- `workbench_settings` 表存 `opportunity_keywords`（JSON：`core`/`secondary`/`exclude` 三档数组），上一迭代由 `WorkbenchStore.__init__` 默认写入 `DEFAULT_KEYWORDS`。
- `search()` 每次调用 `self.setting('opportunity_keywords')` 读最新配置 → **天然保存即生效**（只需加写接口）。
- `GET /api/meta` 已返回 `opportunity_keywords`，前端面板可直接用它初始化。
- 设置页 `#page-settings` 已有多个 `<article class="panel">`（自动更新/团队成员/扩充来源库/全国数据源），新增面板复用同样式。
- `app.js` 已有 `toast()`、`api()`、`esc()`、`refreshMeta()` 等辅助，可复用。

## 4. 后端接口

新增 `PATCH /api/settings/opportunity-keywords`：

- 请求体（JSON）：
```json
{"core": ["服务器", "算力"], "secondary": ["信息化"], "exclude": ["复印纸"]}
```
- 校验规则：
  - 三档均为字符串数组，缺省视为 `[]`
  - 每档去重（保序）、每词 strip、长度 ≤30
  - 单档最多 200 词（超出 400）
- 写入 `store.set_setting('opportunity_keywords', {...})`
- 返回：`{"saved": true, "keywords": {...}}`（保存后的规范化配置）

新增 pydantic 模型：

```python
class OpportunityKeywordsInput(Input):
    core: list[str] = Field(default_factory=list, max_length=200)
    secondary: list[str] = Field(default_factory=list, max_length=200)
    exclude: list[str] = Field(default_factory=list, max_length=200)

    @field_validator("core", "secondary", "exclude")
    @classmethod
    def clean_words(cls, words):
        cleaned = []
        for word in words:
            word = word.strip()
            if word and len(word) <= 30 and word not in cleaned:
                cleaned.append(word)
        return cleaned
```

`web/assets/app.js`：

- `refreshMeta()` 中（或单独函数）填充 textarea：
```javascript
function loadOpportunityKeywords() {
  const kw = state.meta?.opportunity_keywords || {core:[],secondary:[],exclude:[]};
  $('#kwCore').value = (kw.core || []).join('\n');
  $('#kwSecondary').value = (kw.secondary || []).join('\n');
  $('#kwExclude').value = (kw.exclude || []).join('\n');
}
```
（在 `refreshMeta()` 末尾调用，或在页面切换到 settings 时调用一次）

- 保存处理：
```javascript
$('#saveKeywords').addEventListener('click', async function () {
  await busy(this, async () => {
    const body = {
      core: $('#kwCore').value.split('\n'),
      secondary: $('#kwSecondary').value.split('\n'),
      exclude: $('#kwExclude').value.split('\n'),
    };
    await api('/api/settings/opportunity-keywords', 'PATCH', body);
    await refreshMeta();
    $('#kwStatus').textContent = '已保存，相关度计算即时生效';
    toast('关键词已保存');
  });
});
```

- 事件绑定：在既有初始化事件绑定区（`bindEvents()` 或等价函数）追加 `saveKeywords` 监听。

> 注意：先读 `app.js` 确认事件绑定方式（DOMContentLoaded 中直接 addEventListener 还是集中 bindEvents），保持一致。`busy()` 是既有按钮 loading 辅助，确认签名。

## 6. 测试（新增 `tests/test_opportunity_keywords.py`）

1. **PATCH 合法保存**：TestClient PATCH 三档词表 → 200，`meta().opportunity_keywords` 已更新。
2. **保存即生效**：PATCH 后 `search()` 相关度按新词表计算（旧词表不含的词 → 新词命中 → direct）。
3. **非法输入 400**：非数组（如 `"core": "服务器"`）→ 400。
4. **去重与空词清理**：`["", "服务器", "服务器"]` → `["服务器"]`。
5. **超长词拒绝**：单词 31 字符 → 被过滤（不 400，静默丢弃）。
