# AI 精读标书 — 设计文档

- 日期：2026-11-23
- 状态：已确认
- 背景：借鉴 bids-spider 的 deerflow LLM 精读能力，落到本项目团队工作台（Web）
- 迭代边界：子项目 2（本 spec）只做「AI 精读标书」；子项目 1（关键词界面化编辑）已交付
- 前置依赖：机会分析规则引擎（relevance 字段）、公告详情补抓（content/deadline/budget/purchaser）、中标/废标追踪（win_company/win_amount）

## 1. 需求与目标

用户已能通过相关度筛选找到重点商机，但仍需逐条翻原文判断"要不要投"。本子项目让 AI（deerflow CLI）精读公告/标书，输出结构化研判（采购单位/预算/截止/技术要点/业务关联度/跟进建议/风险提示）+ 建议文本，存库并在详情页展示；支持单条/批量手动精读与采集后自动精读。

## 2. 已确认的决策

- **接入方式**：本机 deerflow CLI（仿 bids-spider，`deerflowcli --output-dir --timeout --no-stream [--gateway] [--recursion-limit] <task>`）。
- **触发**：手动（单条 + 批量）+ 可配自动（采集后对直接相关公告，开关 + 每日上限）。
- **产出**：结构化 JSON + 建议文本（JSON 字段：采购单位/预算/投标截止/技术要点/业务关联度/跟进建议/风险提示 + `建议文本` 字段）。
- **输入**：标题 + 结构化字段（金额/截止/采购人/中标）+ 正文前 N 字（`detail_len` 默认 2000）；模型可 `web_fetch` 打开原文核实。
- **方案**：方案 A —— 独立 `ai_read` 模块 + 后台线程（复用 DetailFetcher 模式），结果存 SQLite `ai_reads` 表。
- **精读范围**：单条 + 批量（最多 50 条/次）。

## 3. 现状关键事实（已核实）

- 工作台当前**无任何 AI 代码**；桌面版 `ai_guard.py` 有可复用的"AI 文本→JSON 提取 + 失败降级"模式（剥 ```json``` 围栏 → 取首尾大括号 → json.loads）。
- bids-spider `analyze_opportunities.py`：`load_llm_config()`（.env 读 LLM_ENABLED/DEERFLOW_CLI/DEERFLOW_GATEWAY/DEERFLOW_TIMEOUT/DEERFLOW_RECURSION_LIMIT/LLM_LIMIT/LLM_DETAIL_LEN）、`_locate_deerflow_cli()`（显式路径 → which → 常见目录）、`_run_deerflow()`（subprocess + 心跳 + 超时 kill + 错误分类 + `--thread-id` 会话恢复）、`llm_reads` 缓存 + `input_hash` 指纹。
- 工作台 `CollectionService` 已有可复用模式：`DetailFetcher` 后台线程（queue + pending 扫描 + 限速 + host 冷却）、job snapshot 存 `workbench_settings`、`/api/meta` 返回 collection 状态、`collection_runs` 记录、`workbench_settings` JSON 存取。
- `projects` 表已有 `content/deadline/budget/purchaser/win_company/win_amount`；`search()` 已算 `relevance`。
- 前端：`renderDetail()` 的 `info-grid` 可插入精读结果；设置页 `settings-grid` 可加配置面板。

## 4. 数据模型（新增 `ai_reads` 表）

`WorkbenchStore.__init__` 建表：

```sql
CREATE TABLE IF NOT EXISTS ai_reads (
    project_id TEXT PRIMARY KEY REFERENCES projects(id),
    status TEXT NOT NULL DEFAULT 'pending',
    input_hash TEXT NOT NULL DEFAULT '',
    result_json TEXT NOT NULL DEFAULT '',
    error TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

- `status`：`pending`（待精读）/ `running` / `ready`（成功）/ `error`
- `input_hash`：输入内容 md5，`ready` 且 hash 一致 → 复用缓存不调模型；内容变化 → 自动重读
- `result_json`：`{"采购单位":..., "预算":..., "投标截止":..., "技术要点":..., "业务关联度":..., "跟进建议":..., "风险提示":..., "建议文本":...}`

## 5. AI 精读模块（新文件 `collectors/ai_read.py`）

纯逻辑 + subprocess，无 FastAPI 依赖，可 mock 单测：

### 5.1 配置
- `load_ai_config(store)`：读 `workbench_settings`（key=`ai_read_settings`，JSON）：
```json
{
  "enabled": false,
  "deerflow_cli": "",
  "gateway": "http://127.0.0.1:8001",
  "timeout": 600,
  "recursion_limit": 300,
  "detail_len": 2000,
  "auto_enabled": false,
  "auto_limit": 10
}
```
- `WorkbenchStore.__init__` 无此 key 时写入默认值。

### 5.2 CLI 探测
- `locate_deerflow_cli(conf)`：显式 `deerflow_cli` → `shutil.which('deerflowcli')` → 探测 `~/.local/bin`、`~/bin`、`/usr/local/bin`、`/opt/homebrew/bin` → 都不存在返回 `''`。

### 5.3 提示词构建
- `build_prompt(project, conf)`：拼接标题、结构化字段（预算/截止/采购人/中标单位/金额）、正文前 `detail_len` 字；要求模型输出 JSON（字段见 §4）+ 一段建议文本，可 `web_fetch` 打开原文核实。

### 5.4 执行
- `run_deerflow(task, conf)`：subprocess 调 `deerflowcli --output-dir <tmp> --timeout N --no-stream [--gateway url] [--recursion-limit N] <task>`，扫描输出目录取最新 `.md` 报告；错误分类返回中文提示。
- 错误分类：CLI 缺失 → "未配置 deerflow CLI 路径"；401/API key → "模型凭据无效"；429/限流 → "模型限流"；网关不可达 → "deerflow Gateway 不可达，请确认已启动（curl http://127.0.0.1:8001/health）"。

### 5.5 解析
- `parse_result(text)`：剥 JSON 围栏 → 取首尾大括号 → `json.loads` → 成功返回 dict；失败返回 `{"error": "AI 输出解析失败", "raw": 截断前 500 字}` 降级（不崩溃）。
- `compute_hash(project, conf)`：对标题+字段+正文前 detail_len 字 md5。

## 6. 精读服务（`CollectionService` 新增 `AIReadFetcher` 后台线程）

仿 `DetailFetcher`：

- **队列与扫描**：`request(key)` 入队（单条手动）；`run_once()` 先清队，再扫 `ai_reads` 中 `status='pending'` 或 `(status='ready' AND input_hash != 当前hash)` 的记录（自动入口）。
- **每条流程**：读 project → `compute_hash` → `ready` 且 hash 一致 → 跳过；否则 `status='running'` → `run_deerflow` → `parse_result` → 写 `ai_reads`（ready/error + result_json/error + hash）。
- **限速**：`ai_read_interval`（默认 60 秒/条，串行），避免频繁调本地 Gateway。
- **自动精读**：`tick()` 采集完成后，若 `auto_enabled` 且当日精读数 < `auto_limit`，对 `relevance=direct` 且无 `ai_reads` 记录（或 hash 变化）的公告入队。
- **job snapshot**：`workbench_settings`（key=`ai_read_job`）：`running/message/completed/total/failures`，`/api/meta` 返回展示。
- **生命周期**：`open()` 启动、`close()` 停止，独立 `self.stop`。

## 7. API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/projects/{key}/ai-read` | 单条手动触发（入队 + 返回 `{queued: true}`；未配置 AI 时返回 400 带提示） |
| POST | `/api/ai-read/batch` | 批量（body `{keys: [id,...]}`，≤50；或 `{filter: {"relevance": "direct"}}`） |
| GET | `/api/projects/{key}` | 详情返回 `ai_read`（result_json 解析后 dict + status） |
| PATCH | `/api/settings/ai-read` | 保存 deerflow 配置（enabled/cli/gateway/timeout/recursion_limit/detail_len/auto_enabled/auto_limit） |
| GET | `/api/meta` | 返回 `ai_read_settings` + `ai_read_job` |

新增 pydantic 模型：

```python
class AIReadSettingsInput(Input):
    enabled: bool = False
    deerflow_cli: str = Field(default="", max_length=500)
    gateway: str = Field(default="http://127.0.0.1:8001", max_length=300)
    timeout: int = Field(default=600, ge=60, le=7200)
    recursion_limit: int = Field(default=300, ge=50, le=1000)
    detail_len: int = Field(default=2000, ge=200, le=10000)
    auto_enabled: bool = False
    auto_limit: int = Field(default=10, ge=1, le=100)


class AIReadBatchInput(Input):
    keys: list[str] | None = Field(default=None, max_length=50)
    filter: dict | None = Field(default=None)
```

4. `locate_deerflow_cli`：mock `shutil.which` 与显式路径。
5. AIReadFetcher：mock `run_deerflow`，断言 pending→ready 写库、ready+hash 一致跳过、失败置 error、手动队列优先。
6. API：单条/批量触发、配置保存（PATCH）、详情返回 ai_read、meta 返回配置。
7. 自动精读：mock 采集完成后对 direct 公告入队。

## 10. 明确不做（YAGNI）

- 不做分批并发精读（bids-spider 的 >15 条分批/2 并发）——工作台单机低频串行即可。
- 不做模型可选（固定 deerflow 引擎）。
- 不做精读历史/审计页（详情页展示最新即可）。
- 不做 AI 精读结果导出。

## 11. 成功标准

1. 单条/批量手动精读可触发，结果存 `ai_reads` 并详情页展示。
2. 精读缓存生效（hash 一致不重复调模型）。
3. 自动精读（开关 + 每日上限）在采集后对直接相关公告生效。
4. deerflow 配置可在设置页编辑；未配置时精读返回明确提示（400 + 中文文案）。
5. 新增 `tests/test_ai_read.py` 全 PASS；既有测试不回归。
